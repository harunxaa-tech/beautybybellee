# Cloud sync account boundary and pull safety
2026-11-25. Stage on release branch only. Capture client/company/user/role/workspace and context generation; validate current authenticated context before and after write requests. Explicit company-scoped helpers; old queued retries cannot switch to a different workspace; failed old request cannot write new workspace metadata. Push uses cloned snapshot and only acknowledges matching local revision. Manual refresh is read-only instead of blindly pushing entire snapshot. Pull rejects pending local changes and revision changes during fetch, before replacing collections. Existing pending conflict needs explicit reconciliation: no automatic resolution, preserve local data. Attach while another sync is active rejects instead of swapping shared variables. Actual RLS remains authoritative. An already dispatched server operation can complete for its original company. No guarantee of atomic multi-table writes, conflict-free cross-device edits, tombstones or consistent read snapshots. CloudFiles and other modules still need independent review. Full revision/CAS and dirty-record journal, per-record conflicts, offline recovery, multiple tabs, actual device and network tests remain blockers. Native dependency candidate audit reported zero vulnerabilities but preparation failed on shell quote typo; quote corrected and rerun. No production deployment.
