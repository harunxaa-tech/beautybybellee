# Voice pack payment ledger — prelaunch
2026-11-25. Applied migration voice_pack_payment_order_ledger. Private catalog and order ledger with RLS and no client access. Catalog empty by design: no configured price or sale. Server-only order creation requires active owner and write-eligible subscription; order snapshots fixed SKU, provider price ID, EUR gross amount and seconds. The payment RPC is service-role only and expects a trusted authoritative current Stripe snapshot, NOT client input. Unique PaymentIntent binding and atomic grant update prevent duplicate grants across different orders; same-company quota lock serializes with existing voice consumption. Live-mode proof only; sandbox integration testing needs isolated project/test ledger. Grant expiry 12 months after verified payment time. Partial and full successful refunds revoke remaining credit without changing consumed_units; partial refunds require manual review and a final fair policy before launch. Stale cumulative refund totals rejected. No refund or charge initiated by this code.

Rollback-only SQL test passed: disabled catalog, owner check, sandbox rejection, price amount mismatch, valid grant, exact repeat, cross-order duplicate payment, partial refund, repeated refund, stale refund, full refund and preserved consumption. Final counts orders=0, catalog=0, grants=0. Existing quota grants initially zero. Tested sequentially, not simultaneous DB connections.

Still required: trusted Stripe Checkout creation with durable order ID and provider idempotency; verify PaymentIntent succeeded, amount/currency, actual checkout line price and quantity, company/order binding, provider account, captured amount, full refund list pagination and successful refunds; dispute/chargeback handling; stable paid_at from provider; current authoritative snapshots; transactional event-inbox completion; tax-inclusive price approval; separate sandbox project; actual end-to-end and parallel tests. Prevent client direct invocation. Do not enable catalog before full integration. Storage add-ons are monthly and must use unique invoice line + period grants with renewal, cancellation, expiry and refund semantics; never delete customer files on expired add-on. Not implemented here. No provider calls or new costs.
