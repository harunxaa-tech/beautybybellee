# Stripe durable event inbox — prelaunch
2026-11-25. Migration durable_stripe_event_inbox applied; existing billing_webhook_events left untouched. New private table stores event ID/type/environment only, no Stripe payload. RPCs are service-role only. Enqueue is unique per event ID; conflicting type/environment rejected. Claim uses row locks with SKIP LOCKED, a five-minute lease, bounded retry backoff and ten-attempt limit. Exhausted events are retained as dead, not dropped. A stale token cannot acknowledge a newer attempt.

Direct rollback-only SQL tests passed: enqueue, duplicate, conflicting environment, environment-specific claim, no second live claim, invalid token, expired lease, reclaim with new token, old token rejection, retry/backoff, successful completion, replay exclusion and exhausted retry/dead state. No rows left by the tests. No payment or provider call. These sequential database tests are not proof of multi-connection race behavior.

scripts/stripe-event-inbox.mjs is a staged adapter, NOT a live handler. Before production: raw-body signature and account verification at receiver; durable enqueue before 2xx; provider-authenticated retrieval of current event AND subscription/invoice, never use event.created as ordering proof; transactional business update with lease verification and completion in the same transaction; idempotent paid add-on ledger, per-subscription serialization or compare-and-swap reconciliation; scheduled worker, dead-letter alerts, manual replay authorization, retention and reconciliation of missed notifications; genuine concurrent/sandbox tests. Existing active webhook is unchanged. Do not switch receiver to inbox before worker and recovery are verified. A lease by itself does not fence side effects outside the database. No success adapter exposed intentionally.
