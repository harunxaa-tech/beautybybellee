# Storage add-on paid period ledger — prelaunch
2026-11-25. Applied migration storage_pack_paid_period_ledger. Catalog remains empty; no active products or checkout. Private tables with RLS and revoked client access. Service-only binding requires active owner, active live Stripe subscription, matching company, customer, subscription, item and configured price. Each binding snapshots price, net cents and bytes. Each paid, non-prorated quantity-one EUR monthly invoice line maps to one grant with explicit start and end. Same item cannot receive overlapping period grants; replay reuses the same grant. Revocation is monotonic and shares the existing company storage advisory lock. No function deletes storage objects. Existing authorized read policy is independent of quota. Expired and future grants do not count toward today's quota.

Sequential rollback-only SQL tests passed for unconfigured catalog, owner, bind/replay, unpaid/prorated/amount mismatch, paid grant, duplicate, overlap, past period, future period, revoke and revoked replay. Catalog/bindings/periods/grants all zero afterward. No actual file upload/download or simultaneous DB test was performed. Existing data not permanently changed. UI notice differentiates exact full, over limit, warning, invalid counters without rounding causing false full state.
